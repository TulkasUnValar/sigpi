# Products Specification

## Purpose
Enable institution-scoped registration, classification, and querying of research products generated by projects.

## Requirements

| ID | Requirement | Rule |
|---|---|---|
| RF-080 | Register research products linked to projects | The system MUST allow CRUD of products. Each product SHALL link to exactly one project via FK. |
| RF-081 | Classify by type | Type MUST be one of 11 hardcoded types (artículo, libro, capítulo, software, prototipo, evento, etc. per §6.7). |
| RF-082 | Associate authors | Each product MUST have ≥1 author. A researcher MUST NOT appear more than once per product. Exactly one author MUST be principal. |
| RF-083 | Attach evidence metadata | Attachments MUST store name, doc_type, and external_url only. File upload is out of scope. |
| RF-084 | Query by attributes | The system MUST filter by center, group, line, researcher, project, publication_year (exact/range), and type. All queries MUST be institution-scoped. |
| RF-085 | Meilisearch indexing | Deferred to "Search Integration". |

### RF-080 Scenarios

#### Scenario: Create product linked to project
- GIVEN an authenticated user with a valid project in their institution
- WHEN the user POSTs a product with title and project id
- THEN the system creates the product and returns it with a UUID

#### Scenario: Reject product without project
- GIVEN an authenticated user
- WHEN the user POSTs a product without a project id
- THEN the system responds with 400 Bad Request

#### Scenario: Reject foreign project link
- GIVEN a user in institution A
- WHEN the user POSTs a product linked to a project in institution B
- THEN the system responds with 404 Not Found

### RF-081 Scenarios

#### Scenario: Accept valid type
- GIVEN an authenticated user
- WHEN the user POSTs a product with type "artículo"
- THEN the system creates the product successfully

#### Scenario: Reject empty type
- GIVEN an authenticated user
- WHEN the user POSTs a product with type ""
- THEN the system responds with 400 Bad Request

#### Scenario: Reject invalid type
- GIVEN an authenticated user
- WHEN the user POSTs a product with type "patente"
- THEN the system responds with 400 Bad Request

### RF-082 Scenarios

#### Scenario: Add principal and co-authors
- GIVEN a product with no authors
- WHEN the user adds two authors and marks one principal
- THEN both authors are stored with exactly one principal flag

#### Scenario: Reject duplicate researcher
- GIVEN a product with researcher X as author
- WHEN the user adds researcher X again
- THEN the system responds with 400 Bad Request

#### Scenario: Reject missing principal
- GIVEN a product with one co-author not marked principal
- WHEN the user attempts to save
- THEN the system responds with 400 Bad Request

### RF-083 Scenarios

#### Scenario: Add metadata attachment
- GIVEN an existing product
- WHEN the user POSTs an attachment with name, doc_type, and external_url
- THEN the system stores the metadata linked to the product

#### Scenario: Reject empty external_url
- GIVEN an existing product
- WHEN the user POSTs an attachment with external_url ""
- THEN the system responds with 400 Bad Request

#### Scenario: Reject missing external_url
- GIVEN an existing product
- WHEN the user POSTs an attachment without external_url
- THEN the system responds with 400 Bad Request

### RF-084 Scenarios

#### Scenario: Filter by year range and type
- GIVEN products with years 2023–2025 and mixed types
- WHEN the user queries with year__gte=2024 and type=artículo
- THEN only matching products from the user's institution are returned

#### Scenario: Empty result for foreign institution
- GIVEN a product in institution A
- WHEN a user from institution B queries all products
- THEN the system returns an empty list

### Business Rules

- `publication_year` MUST be an integer between 1900 and current_year+1.
- Institution scoping MUST apply to all queries.
