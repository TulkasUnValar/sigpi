# Proposal: Research Products (SIGPI §6.7)

## Intent
Enable research groups to register, classify, and query products generated by projects — articles, books, software, events, etc. Replaces ad hoc spreadsheets with structured, institution-scoped records.

## Scope

### In Scope
- New `backend/apps/products/` app (models, API, tests, admin)
- `ResearchProduct`: type, title, year, description, project FK
- `ProductAuthor` junction: researcher FK, principal flag
- `ProductAttachment` metadata: name, doc_type, external_url
- DRF filtering by center, group, line, researcher, project, year, type
- RLS activation for new tables

### Out of Scope
- Meilisearch indexing (RF-085) — deferred to "Search Integration"
- Actual file upload (RF-083) — metadata-only `external_url` per MVP precedent
- Frontend pages (backend-only slice)
- Budget/call linkage

## Capabilities

### New Capabilities
- `products`: CRUD for research products, authors, attachments with filtering and institution scoping

### Modified Capabilities
- None (pure addition)

## Approach
Standalone app following `progress`/`projects` ViewSet pattern. UUID PKs, denormalized `institution_id` for RLS, `django-filter`, nested ViewSets for authors/attachments. No FSM.

## Affected Areas

| Area | Impact | Description |
|------|--------|-------------|
| `backend/apps/products/` | New | Models, serializers, views, permissions, filters, urls, tests, admin |
| `backend/config/settings/base.py` | Modified | Add `"apps.products"` to `LOCAL_APPS` |
| `backend/config/urls.py` | Modified | Include `apps.products.urls` under `/api/products/` |
| `backend/apps/accounts/migrations/0004_rls_policies.py` | Modified | Add product tables to `TENANT_SCOPED_TABLES` |

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| RLS tables forgotten | Low | Checklist in apply tasks; migration review |
| Filter performance on researcher join | Low | Index `(product, researcher)`; `prefetch_related` |

## Rollback Plan
1. Revert `INSTALLED_APPS` and `urls.py`
2. Drop `backend/apps/products/` directory
3. Remove RLS entries; fake-reverse migration if tables exist

## Dependencies
- `projects` (Project FK target)
- `researchers` (Researcher FK target)
- `institutions` (scoping)

## Success Criteria
- [ ] `GET/POST /api/products/` scoped to institution works
- [ ] Filtering by center, group, line, researcher, project, year, type works
- [ ] Nested author/attachment endpoints work
- [ ] RLS enforces tenant isolation on all three tables
- [ ] 100% backend test coverage for new app

## Proposal Question Round

Answer these to finalize scope and business rules:

1. **File upload vs metadata-only**: RF-083 says "upload documentary evidence". Should MVP store only `external_url` metadata (consistent with ProjectDocument/ProgressDocument), or do you require actual file upload (MinIO/S3) in this change?
2. **Author rules**: Can a researcher appear multiple times on the same product? Should exactly one principal author be enforced, or can there be multiple?
3. **Year semantics**: Should `year` represent publication year, registration year, or both? Is a range query needed, or just exact match?
4. **Backend-only or + frontend**: Include Next.js pages (list, create, detail), or backend API slice only for now?
5. **Product type extensibility**: The 11 types from SPEC §6.7 are hardcoded. Should admins add types dynamically, or is a code change acceptable for new types?
